The inference app implements the [x402 protocol v2](https://x402.fi) for payment-gated HTTP endpoints. The inference API at `/api/inference` requires a USDC payment before running any model.

---

## x402 Protocol Overview

x402 adds a payment layer to standard HTTP. The flow uses HTTP status code 402 (Payment Required) as a machine-readable signal:

```
1. Client sends request without payment → server returns 402 with payment details
2. Client signs a payment authorization (EIP-712 + EIP-3009)
3. Client resends request with signed payment in header
4. Server submits payment to the x402 facilitator (verify + settle)
5. Settlement confirmed → server runs the requested operation → returns 200
```

This flow works for both human users (signing via their wallet) and autonomous agents (signing programmatically).

---

## The Two-Phase Flow in Detail

### Phase 1 — 402 Challenge

`POST /api/inference` with no `Payment-Signature` header:

```
Server response:
  Status: 402 Payment Required
  Header: Payment-Required: <base64-encoded PaymentRequiredResponse>
  Body: { estimatedCostUsdc, estimatedSeconds, ratePerSec }
```

The `PaymentRequiredResponse` contains:

```typescript
{
  version: "2",
  accepts: [{
    scheme: "exact",
    network: "eip155:1",           // or "eip155:11155111" for Sepolia
    asset: "0xA0b86991...",        // USDC contract address
    amount: "10000",               // in USDC base units (6 decimals)
    extra: {
      name: "USD Coin",
      version: "2",                // EIP-712 domain version
    },
    payTo: "0xRECEIVER_ADDRESS",   // from RECEIVER_ADDRESS env var
    maxAmountRequired: "10000",
    resource: "https://app.webai3.xyz/api/inference",
  }],
  error: ""
}
```

The `amount` is calculated as:

```
estimatedSeconds = historicalAvg(model, task) ?? taskDefault
amount = ceil(estimatedSeconds * ratePerSec * 1_000_000)  // to 6-decimal USDC units
```

### Phase 2 — Signed Payment

Client re-sends `POST /api/inference` with the `Payment-Signature` header set to a base64-encoded `PaymentPayload`:

```typescript
{
  scheme: "exact",
  network: "eip155:1",
  payload: {
    signature: "0x...",  // EIP-712 TransferWithAuthorization signature
    authorization: {
      from: "0xUSER_ADDRESS",
      to: "0xRECEIVER_ADDRESS",
      value: "10000",
      validAfter: 1234567890,     // 10 minutes before now
      validBefore: 1234568490,    // 10 minutes after now
      nonce: "0xRANDOM_BYTES32",  // random, one-time nonce
    }
  }
}
```

The server:
1. Decodes the `Payment-Signature` header
2. Calls `verifyWithFacilitator(payload, requirements)` → confirms the signature is valid
3. Calls `settleWithFacilitator(payload, requirements)` → submits on-chain transfer, gets tx hash
4. Persists the inference record with `payment_tx_hash` (UNIQUE constraint prevents replay)
5. Runs the model on Replicate
6. Uploads media to R2, stores R2 keys in database
7. Returns `200` with the inference result

## EIP-3009 — TransferWithAuthorization

USDC implements EIP-3009 (`transferWithAuthorization`). The signature authorizes a specific transfer without requiring a separate on-chain `approve()` call.

### EIP-712 Domain (USDC on Ethereum Mainnet)

```
domain = {
  name: "USD Coin",
  version: "2",
  chainId: 1,
  verifyingContract: "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48"
}
```

### TransferWithAuthorization Type

```
types = {
  TransferWithAuthorization: [
    { name: "from",        type: "address" },
    { name: "to",          type: "address" },
    { name: "value",       type: "uint256" },
    { name: "validAfter",  type: "uint256" },
    { name: "validBefore", type: "uint256" },
    { name: "nonce",       type: "bytes32" },
  ]
}
```

### Validity Window

The client sets:
- `validAfter = now - 10 minutes` (grace period for clock drift)
- `validBefore = now + 10 minutes` (authorization expires after 10 minutes)

This gives a 20-minute window in which the facilitator can accept the signature.

### Nonce

The nonce is a random `bytes32` generated by the client (`crypto.randomBytes(32)`). It's consumed once by the USDC contract's `transferWithAuthorization` — subsequent attempts with the same nonce revert.

The inference app also enforces uniqueness via the database `UNIQUE` constraint on `payment_tx_hash`.

## The x402 Facilitator

The facilitator is a third-party service that:
1. **Verifies** the EIP-712 signature offline
2. **Settles** the payment by calling `transferWithAuthorization` on the USDC contract

Default facilitator: `https://facilitator.x402.fi` (operated by RelAI)

The facilitator supports `eip155:1` (Ethereum mainnet). For Sepolia testing, the inference app uses Anvil local dev mode where payment settlement is mocked (a UUID is used as the fake tx hash).

### Facilitator API

```typescript
// Verify (no on-chain action — fast)
POST https://facilitator.x402.fi/verify
Body: { paymentPayload, paymentRequirements }
Response: { isValid: boolean, invalidReason?: string }

// Settle (on-chain — slower, gas required)
POST https://facilitator.x402.fi/settle
Body: { paymentPayload, paymentRequirements }
Response: { txHash: string, networkId: string }
```

Settlement order: settle happens BEFORE inference. Once settled, payment is irrevocable. If Replicate fails after settlement, the error is logged and the tx hash is recorded, but no refund is issued.

## Cost Calculation

### Estimation (Phase 1)

```typescript
async function historicalEstimateSeconds(db, model, task): Promise<number> {
  // Query avg predict_time_ms for this model in last 100 inferences
  const avg = await db.query(
    `SELECT AVG(predict_time_ms) FROM inferences
     WHERE model = $1 AND status = 'succeeded'
     ORDER BY created_at DESC LIMIT 100`,
    [model]
  );
  if (avg) return avg / 1000;
  return TASK_CONFIGS[task].estimatedSeconds; // fallback
}

const estimatedCostUsdc = estimatedSeconds * ratePerSec;
```

### Actual Cost (Post-Inference)

```typescript
const actualCostUsdc = (predictTimeMs / 1000) * ratePerSec;
```

The payment is settled for the *estimated* amount. The actual cost is recorded for analytics. The amounts can differ — actual inference might be faster or slower than the estimate.

### Rate

Default: `INFERENCE_RATE_PER_SEC = 0.001` (USDC/second). Configurable via env var.

With staking discounts (Tier 1):

```
effectiveRate = baseRate * (1 - discountPct)
```

## Inference Execution

After payment is settled:

1. **Create Replicate prediction:**
   ```typescript
   const prediction = await replicate.predictions.create({
     version: modelVersion,
     input: parsedInput,
   });
   await replicate.wait(prediction);
   ```

2. **Handle output by type:**
   - `text-to-text`: output is a string array, joined and stored in `outputData` JSONB
   - `text-to-image`, `text-to-sound`: output contains URLs to Replicate CDN

3. **Upload media to R2:**
   ```typescript
   async function uploadMediaToR2(sourceUrl, walletAddress, inferenceId, index) {
     // validates sourceUrl is from replicate.delivery or replicate.com domain
     // fetches media (60s timeout)
     // uploads to R2 with key: {walletAddress}/{inferenceId}/{index}.{ext}
     // returns R2 key (permanent URL, not expiring Replicate URL)
   }
   ```

4. **Persist to database:**
   - On success: status=succeeded, r2Keys, actualCostUsdc, predictTimeMs
   - On failure: status=failed, errorMessage (sanitized Replicate error)

## Replay Protection

Three layers prevent payment replay:

| Layer | Mechanism |
|---|---|
| EIP-3009 nonce | USDC contract records each `nonce` as used; re-use reverts on-chain |
| Validity window | `validBefore` timestamp in the authorization; stale signatures expire |
| Database constraint | `payment_tx_hash` is `UNIQUE`; duplicate tx hash insertion fails |

## Local Dev Mode (Anvil)

When `NEXT_PUBLIC_ENABLE_DEV_CHAIN=true` and `chainId == 31337`:
- `verifyWithFacilitator` is skipped
- `settleWithFacilitator` is skipped
- A UUID is used as the fake tx hash
- Inference runs normally (still calls Replicate)

This allows full end-to-end testing without a real on-chain settlement or mainnet USDC.
